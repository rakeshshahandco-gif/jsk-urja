Always start as Super Admin. Do not create users or masters until Steps 1–4 below are done. Wrong order is the #1 reason menus are missing or too many modules appear.

Quick decision — where do I start today?

  • Brand-new Handloom company → Start at Step 1 (verify TEXTILE_HANDLOOM) then Steps 2 → 3 → 4.
  • Company exists but wrong menus → Start at Step 3 only. Check template + Save allocation. Re-login.
  • Menus OK but fields/forms wrong → Start at Step 4 (Feature Configuration). Do not change modules unless menu is wrong.
  • JSK electronics (legacy) → Step 2 + profile only until you intentionally configure Step 3.

Three setup layers

Configure the platform top-down. Each layer builds on the previous one; skipping a layer causes missing menus, blocked APIs, or wrong defaults.

1Platform / Industry Industry Template Master (/admin/industry-templates), platform feature defaults, workflow master. Defines template codes (e.g. TEXTILE_HANDLOOM, ELECTRONICS_JSK) and default module sets.
2Module allocation Per-company enablement at /admin/module-allocation. Sets enabledModules, optional disabledModules, links industryTemplateRef, and turns on moduleGuardEnabled when allocation is configured.
3Feature settings Feature Configuration Engine at /admin/feature-compliance-settings (legacy alias /admin/feature-configuration). Toggles compliance, customer fields, GST, inventory behavior, and registry overrides per company.
Company master data Create/edit company at /admin/companies and legal profile at /company-profile (company Admin). Assign financial year, GST, and users after layers 1–3.
Order of operations: Template → Company record → Module allocation (Apply template defaults) → Feature settings → Users & permissions → Masters (items, ledgers, groups).

Roles: Super Admin vs Admin

Super Admin (superadmin)
  • Full platform menus: SaaS, industry templates, module allocation, platform feature defaults, diagnostics, backups.
  • Only role that may open platform paths under /admin/industry-templates, /admin/module-allocation, /admin/platform-feature-defaults, /admin/companies (platform list).
  • Sees Engine tabs in Feature Configuration (Modules, Registry → Compliance/Customer/Supplier/Industry).
  • Non–Super Admin users hitting platform routes are redirected to platform access denied.
Company Admin (admin)
  • Manages day-to-day setup inside an allocated company: users, permissions, company profile, masters.
  • Uses Feature Configuration Company tabs only (Customer, Sales, GST, Inventory, etc.).
  • Cannot change industry templates or cross-tenant module allocation unless granted Super Admin.
  • Module guard still applies: menus and APIs for disabled modules are hidden/blocked.

Permission model (summary)

Module allocation controls which modules exist for a company. Role permissions control what a user may do inside enabled modules. Configure users at /admin/users and fine-grained permissions via the permissions API / SaaS permission UI groups.

Already logged in as JSK Company Admin? Role admin is not the same as superadmin. Company Admin can create staff users for JSK, but cannot create Super Admin users or open platform pages (Industry Templates, Module Allocation, Companies list). For those steps you must log in with a superadmin account.

Step A — Confirm which role you have now

  1. After login, open sidebar. If you see Super Admin → Platform Setup → Industry Template Master, you are already Super Admin — use that session for setup steps 1–4.
  2. If you only see normal ERP menus (Sales, Purchase, etc.), you are Company Admin — continue to Step B.
  3. Optional: open your user profile / user list and check Role column — must show superadmin, not admin.

Step B — Log in as Super Admin

  1. Logout from your current Company Admin session.
  2. Login with the platform owner account. On fresh installs the default is username admin with role superadmin (password set during first install / seed).
  3. If default login does not show Super Admin menus, your admin user may have been downgraded to Company Admin — a developer or DBA must promote that user in the database (roleName: superadmin).

Industry Template Master

URL: /admin/industry-templates · Super Admin only

  1. Open Industry Template Master → Add or edit an existing row.
  2. Set Template name, unique Template code (uppercase snake case), description, active flag.
  3. Configure template settings sections: Module, Field, Workflow, SOP, Production Process, Document, Report, Dashboard.
  4. Use panels: Customer fields, Supplier fields, Item fields, Documents/KYC, default module list.
  5. Save and ensure isActive is on before linking companies.

Module allocation — step by step

URL: /admin/module-allocation

1
Log in as Super Admin and select the target company.
2
Choose Industry template from the dropdown (loaded from active templates).
3
Click Apply template defaults — sets enabledModules from template, sets moduleAllocationConfigured and moduleGuardEnabled true.
4
Review modules by group (core, textile, electronics, finance, admin). Toggle individual module codes on/off.
5
Optional: add disabledModules to force-off modules that remain in the enabled list (subtractive override).
6
Optional deployment block: database name, backend URL, frontend URL, deployment status (multi-deployment tracking).
7
Save — refreshes module guard context; users may need re-login to see menu changes.

  • engine-module — Modules registry overrides
  • engine-compliance — Registry → Compliance
  • engine-customer — Registry → Customer

Customer · Industry / Production · Sales · GST · Inventory · Accounting · TDS/TCS · Manufacturing · SaaS/Permissions · Purchase · Workflow / Kanban · UI Customization · CRM · Communication

Users and permissions

  1. Ensure company is selected and modules allocated.
  2. Open /admin/users (Company Admin) — create users, assign role (admin, viewer, custom).
  3. Grant permissions only for enabled modules; denied module APIs return guard errors.
  4. Super Admin accounts are separate platform operators — do not use for daily Handloom operators.
  5. After permission changes, users should refresh or re-login for menu cache updates.
  6. WhatsApp / bulk / email modules require both module allocation and communication feature toggles.

New Handloom company — full checklist

  • ☐ Create or verify TEXTILE_HANDLOOM industry template (active)
  • ☐ Create company at /admin/companies and link template
  • ☐ /admin/module-allocation → Apply template defaults → enable textile modules (job work, dyeing, lot tracking, fabric purchase, etc.)
  • ☐ Confirm pcb, bom, smd electronics modules are off
  • ☐ /admin/feature-compliance-settings — Customer/KYC, GST, inventory, manufacturing flags for textile
  • ☐ Company profile + FY + invoice series
  • ☐ Item groups, items, multi-UOM / conversion masters if used
  • ☐ Account groups and ledgers; GST ledgers mapped
  • ☐ Textile job work rate master → issue challan → return entry workflow tested
  • ☐ Task groups and messenger groups for operations team
  • ☐ Users, roles, permission UI groups
  • ☐ WhatsApp module connected (if allocated) and test message
  • ☐ Sample sales invoice + stock movement smoke test
